# Design

## Deliberate omissions

| Considered | Decision | Reason |
|---|---|---|
| MediatR | Rejected | One query, one handler, one caller. Indirection buys nothing. Also now commercially licensed (v13+, Lucky Penny Software) — a licence question is an unforced complication in a hiring artefact |
| FastEndpoints | Rejected | Brief says ASP.NET Core. Third-party framework means the reviewer learns a library to review 40 lines. The REPR benefit is achievable with a Minimal API endpoint class |
| FluentValidation + validation pipeline behaviour | Rejected | One integer parameter |
| MediatR logging behaviour | Rejected | ASP.NET Core already logs requests. Telemetry that matters here is on the refresh path |
| Ardalis.Result | Rejected | Principle is right; this endpoint has one negative outcome. A dependency carrying one case |
| Redis / distributed cache | Rejected | Single instance. Belongs in the scale-out discussion |
| Inbound rate limiting | Rejected | Once the cache is warm, inbound load never reaches Hacker News. The cache *is* the decoupling. Inbound limiting would protect our own CPU, which is a different requirement than the one set |
| Firebase change subscription (streaming) | Rejected for now | Official .NET Firebase SDK does not cover Realtime Database streaming — would need a community package. Long-lived stream needs reconnect **and resync on reconnect**, converting a freshness problem into a correctness problem. May not survive a corporate proxy on the reviewer's machine |
| A higher concurrency cap for the first refresh only | Rejected | Measured, not assumed: raising the cap to 50 for the cold fetch takes startup from ~3.5s to ~1.9s, and 100 reaches ~1.7s, where .NET's own startup dominates. So the saving is real — around 1.6 seconds — but it is spent once per process start, and it buys a second code path, a second number to justify, and a burst of 50 connections against a free, unauthenticated API at the moment we know least about its health. A restart is not a hot path |
| Hand-built HTML UI | Rejected | Backend test. Scope outside the brief in a skill not being assessed |
| Clean Architecture 4-project split (Domain/Application/Infrastructure/Api) | Rejected | One endpoint. Folders within one project carry the same separation at a tenth the navigation cost |
| Moq | Rejected | v4.20 shipped SponsorLink, which read the developer's git email at build time. Withdrawn since, but the trust question outlives the code, and it is the same unforced licence complication as MediatR. NSubstitute costs nothing to switch to |
| FluentAssertions | Rejected | v8 moved to a paid commercial licence (Xceed). Shouldly is BSD-licensed and reads the same |
| WireMock / mock HTTP server | Rejected | A ~20-line `HttpMessageHandler` stub programs per-URL responses and counts calls. A dependency to avoid twenty lines |
| API versioning (`Asp.Versioning.Http`, `/v1/` route prefix, version pinned to Hacker News) | Rejected | A version number is a promise to *our* consumers about *our* contract; Hacker News' `v0` is a property of theirs. The two lifecycles are independent — an upstream change we absorb in the mapper is invisible to callers, and a rename of our own would need a bump while upstream sat still. Tying them means bumping for changes nobody can observe, or being unable to bump for changes they can. The versioning package then buys negotiation, version readers and a deprecation policy for one endpoint, all inert. Hacker News is the cautionary tale: `v0` since 2014, never bumped. What actually insulates callers is that the response DTO is ours rather than a passthrough of upstream item JSON, so an upstream break is one mapping function to fix |


## Decisions taken at setup

Tooling and configuration chosen at setup, and therefore present in the first commit.

| Decision | Rationale |
|---|---|
| Scalar (`Scalar.AspNetCore`) for the OpenAPI UI | .NET 9 removed the bundled Swagger UI: the framework generates the document, rendering is the caller's problem. Scalar renders the built-in document with no second generator, so Swashbuckle is not needed. `/` redirects to it, in Development only, so a reviewer opening the host can exercise the API rather than meet a 404 |
| xUnit | Default for .NET, no learning cost for the reviewer. `WebApplicationFactory<Program>` needs `public partial class Program` — the one line added to `Program.cs` |
| NSubstitute | No SponsorLink history, no licence question, terser syntax than Moq. Little used regardless: upstream is stubbed with a hand-rolled `HttpMessageHandler` |
| Shouldly | Assertion failures name the expression that failed. BSD-licensed, which FluentAssertions v8 no longer is |
| coverlet (`XPlat Code Coverage`) + ReportGenerator | coverlet writes per-method cyclomatic complexity into the Cobertura report; ReportGenerator's Risk Hotspots turns that plus per-method coverage into **CRAP scores**. Two CLI tools, no server, no account |
| Stryker.NET | Coverage proves a line ran; mutation proves the test would fail if the line were wrong. Run locally, score quoted in the README — scheduled nightly rather than per-commit in a real deployment |
| Central package management (`Directory.Packages.props`) | Three projects already share seven packages. Versions drift silently otherwise; one file makes a mismatch a merge conflict instead of a runtime surprise |
| Hacker News base URL in `appsettings.json` (`HackerNews:BaseUrl`) | The `v0` in `https://hacker-news.firebaseio.com/v0/` is a version pin. Held in configuration it is one visible, deliberate line a reviewer can find and a deployment can override; hard-coded it becomes an accident of a string literal repeated wherever a call is made. Trailing slash is load-bearing — `HttpClient.BaseAddress` drops the last segment without it |

## Decisions taken during implementation

Decisions made while building, where the reasoning is not evident from the code alone.

| Decision | Rationale |
|---|---|
| `n` bound as text and parsed by hand, rather than as `int?` | Bound as `int?`, parameter binding answers a non-integer before the endpoint runs, with a different body from the endpoint's own 400 — in Development one carrying the exception type as its title and a stack trace in the payload, in Production a bare `Bad Request` with no `detail`. Taking `n` as text gives every invalid value — missing, `0`, `-1`, `abc`, or one too large to be an `int` — a single identical `ProblemDetails`, and puts the rule in one pure function that unit tests can reach. The cost is that the generated OpenAPI parameter is typed `string`, so an operation transformer restores `integer` with `minimum: 1` |
| OpenAPI examples serialised from a real `StoryDto` | Generated from the schema alone, the API reference shows `"string"` placeholders and a `Z`-suffixed time — contradicting the ISO-8601-with-offset format the brief specifies and the endpoint returns. Running the brief's own example story through the same serialiser that writes responses means the documented sample cannot claim a format the API does not produce |
| `RefreshInterval` configured as a `TimeSpan`, bounded to between a second and a day | A `TimeSpan` keeps the unit in the value rather than in the identifier, and cannot be confused with a plain count the way an `int` can. The cost is a real trap: `TimeSpan.Parse` reads a bare number as days, so an operator setting `30` intending seconds gets a snapshot that refreshes monthly, silently and with no error. The bounds turn that into a startup failure naming the trap. The rejected alternative, an int `RefreshIntervalSeconds`, is unambiguous but puts the unit in the name — which stops scaling once a second duration setting joins it and the two must agree on units. It is a close call, decided on expression rather than cost: the interval is read once, when the timer is constructed, so no conversion is on any hot path |
| Partial transport failure treated as total: a cycle with any unfetchable item is discarded | Publishing 198 of 200 stories would make `n=200` return 198, and the clamping rule would then be hiding a failure rather than reporting a ceiling — two different causes behind one response. Discarding makes partial and total failure behave identically, so clamping keeps a single meaning. The cost is freshness, which is the thing already being traded |
| `null`, `deleted` and `dead` items skipped rather than treated as failures | Verified against the live API: an unknown id returns **200 with a body of `null`**, not a 404. Treating that as a cycle failure would be a live bug — it returns 200, so it never retries, and one deleted story would freeze the snapshot permanently while every health signal stayed green. Skipping yields a snapshot of 199, which the clamping rule already covers |
| Resilience timings surfaced as `UpstreamAttemptTimeout` and `RetryDelay` rather than left at the standard defaults | The standard handler's defaults are sound for production, but nothing could shorten them for tests: `Configure(IConfigurationSection)` reads eagerly, before a test host's configuration exists, and a second `AddStandardResilienceHandler` would stack a second pipeline. Deriving the pipeline from two bound settings makes the timings testable and visible, and the total-request and circuit-breaker windows are derived from the attempt timeout so they cannot be configured into an invalid combination |
| Cold start answered with `503` and `Retry-After`, rather than blocking startup or fetching on demand | Blocking startup until the first snapshot was the earlier behaviour, and surviving upstream failure made it worse: retries lengthen a struggling first cycle, and because Kestrel does not listen until startup finishes, a slow upstream meant no health endpoint either — an orchestrator sees nothing, restarts, and loops. Serving immediately and answering `503` makes the cold window visible and bounded. Rejected: blocking the first request until warm, which makes one caller wait seconds for no signal; and fetching synchronously on a cold miss, which is the most code and reintroduces the need for single-flight |
| Liveness deliberately runs no checks at all | `/health` is mapped with a predicate that matches nothing, so answering *is* the signal: the process is up, the thread pool is not wedged, Kestrel is accepting. It looks like a stub and is not. The tempting alternative — have liveness check Hacker News, or the snapshot — turns someone else's outage into a restart of every instance, and restarting fixes nothing they broke. Here it would be actively harmful: the snapshot lives only in memory, so a restart during an upstream outage discards the last good snapshot and leaves a service that was degraded-but-serving returning 503 until upstream returns |
| Liveness and readiness split across `/health` and `/health/ready` | They answer different questions and a restart is the wrong response to one of them. A cold instance is starting normally: readiness says do not send it traffic, liveness says do not kill it. Collapsing them would have an orchestrator restart every instance during its own startup |
| Request activity recorded in the endpoint, not in middleware | Middleware would count every inbound request, including the health probes an orchestrator sends every few seconds — which would make an instance permanently "in use" and the idle gate decorative. Only a request for stories counts as somebody wanting stories |
| Startup counts as activity | The last-request time starts at construction rather than empty, so a service nobody has called yet still builds its first snapshot instead of waiting for a request it would have to answer with a 503, then refreshing on the following cycle |
